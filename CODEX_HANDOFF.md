## Как перенести на внешний сервер

Сначала на компьютере с готовыми коммитами сохранить этот файл в Git и передать ветку
на remote, на который у пользователя есть право записи. Не считать origin пригодным
для push: он указывает на учебный upstream. Push, смену remote и создание fork
в этом чате пользователь не поручал.

После передачи ветки в серверном checkout:

```sh
git fetch <remote>
git switch --track <remote>/05-system-stats-daemon
# Если локальная ветка уже существует: проверить её состояние и upstream,
# не выполнять reset и не перетирать локальные изменения.
git log -4 --oneline
git status --short --branch
```

Если remote недоступен, можно передать Git bundle с веткой и получить её из bundle.
Конкретный способ переноса согласовать с владельцем окружения. Одного этого файла
для разработки недостаточно: нужны коммиты проекта и исходные ТЗ из репозитория.

### Время, окна и история

- N/M — положительные целые секунды; N 1..3600, M 1..серверный предел.
- Предел M по умолчанию 3600; текущая конфигурация допускает его уменьшение до 1, увеличение выше 3600 требует отдельного решения.
- N > M разрешено; между окнами возникают промежутки.
- Клиентские defaults N=5, M=15. Нулевые значения запроса не означают default.
- Первый снапшот через M секунд после принятия запроса конкретного клиента, даже при существующей истории.
- Следующие ответы через N секунд; расписание привязано к запросу, не к завершению предыдущей обработки.
- Сбор раз в секунду независимо от числа клиентов; захват пакетов непрерывный.
- История ограничена максимальным M с запасом для разностей счётчиков.
- Окно полуоткрытое `[window_start, window_end)`, времена UTC; все секции относятся к одному окну.
- `generated_at` — время формирования; `last_sample_at` — последнее измерение подсистемы.

### Агрегация и единицы

- Load average: три системных значения за 1/5/15 минут усредняются по M; без нормализации на число CPU.
- CPU: проценты из разностей накопительных счётчиков, суммарно по логическим CPU.
- user включает nice; system включает irq/softirq; idle только idle; iowait и steal отдельно. Guest не считать повторно. Три обязательных поля не обязаны давать 100%.
- Disk I/O: завершённые операции чтения+записи/сек и KiB/сек по целым блочным устройствам; разделы исключить, разные устройства автоматически не суммировать.
- KiB=1024 байт, MiB=1024² байт; имена полей отражают единицы.
- Файловые системы: used=total-free, процент=used/total*100; inode аналогично. База процента — total, не доступное непривилегированному пользователю пространство.
- Заполненность: средние использованные MiB, inode и проценты; проценты усредняются отдельно, inode может быть дробным средним. Неопределённый процент при total=0 отсутствует.
- Файловые системы идентифицируются по mount point; служебные/виртуальные исключаются.
- Средние взвешиваются по времени. При пропусках используются пригодные интервалы, без подстановки нулей; статус PARTIAL и coverage_ratio показывают неполноту.
- Слушающие сокеты и количества TCP-состояний — последнее состояние к концу окна, не среднее.
- Сброс счётчика/перезапуск устройства: интервал исключается, отрицательных скоростей нет.

### Сеть

- Linux top talkers использует внешний tcpdump. IPv4/IPv6, входящий/исходящий трафик; loopback по умолчанию исключён; интерфейсы будут настраиваться.
- Учитываются IP-байты с IP-заголовком, без канального заголовка.
- Поток направленный: source IP/port → destination IP/port + IP protocol number.
- Протоколы без портов имеют отсутствующие поля портов, не нулевые значения-заглушки.
- Protocol number открыт для неизвестных значений: TCP=6, UDP=17, ICMP=1, ICMPv6=58.
- По протоколам выдаются все, сумма байтов за окно и процент от всего учтённого IP-трафика; сортировка по убыванию процента.
- По потокам — bytes_per_second (байты, не биты), top-20 по умолчанию, размер будет настраиваться.
- При равенстве: протоколы по номеру; потоки по source IP/port, destination IP/port, protocol; IP сравниваются строками, отсутствующий порт предшествует присутствующему.
- Ограничение количества отслеживаемых потоков обязательно; превышение даёт PARTIAL. Ограничение выдачи top-K само по себе не означает потери учёта.
- TCP-состояния — канонические строки, например ESTABLISHED/SYN_RECV/FIN_WAIT1; неизвестные состояния сохраняются.
- UDP «слушающие» сокеты — локально привязанные. Сокет может иметь нескольких владельцев; передаётся список. При отсутствии прав список пуст, отдельные command/PID/user могут отсутствовать.
- Права для capture и чужих процессов документируются; недоступность не подменяется нулями.

### Ошибки и клиенты

- Сбой одного сборщика не останавливает остальные или весь поток.
- Для каждой из шести подсистем отдельные status/data; все секции и статусы присутствуют в ответе.
- UNSPECIFIED не считается успехом.
- OK: полные данные, coverage_ratio=1; data присутствует, даже с пустыми списками.
- PARTIAL: пригодные, но неполные данные; data присутствует. Coverage может быть 1 при потерях, не связанных с длительностью (лимит потоков).
- DISABLED/UNAVAILABLE: data отсутствует, coverage_ratio=0, last_sample_at отсутствует.
- Для моментальных метрик coverage отражает доступность периодического сбора, данные относятся к last_sample_at.
- Очередь клиента — один ожидающий снапшот, заменяемый более свежим при отставании; отправка ограничивается таймаутом. Медленный клиент не блокирует сбор/остальных.
- Неправильные N/M сервер отклонит InvalidArgument. Валидация RPC, backpressure и listener ещё не реализованы.

- protoc нужно установить на сервере для его ОС, с include-файлами. CLI `protoc --version` → `libprotoc 36.2`; в generated headers может быть `v7.36.2` — это ожидаемое кодирование версии.
- Повторная генерация проверена SHA-256, файлы идентичны; несовпадающий protoc отклоняется.
- Тесты `pkg/api/stats/v1/stats_test.go`: presence, measured zero vs unavailable, empty success, optional port/inode, IPv6, multiple owners, unknown states, metadata round trip.

### Задача 4: конфигурация и CLI (завершена)

- `internal/config/config.go`: `Config`, `Subsystems`, `Default() Config`, `(Config).Validate() error`.
- Config: Port int, MaxWindowSeconds int, Subsystems с шестью bool.
- Defaults: port 50051, max window 3600, все подсистемы true.
- `internal/config/json.go`: `LoadJSON(io.Reader) (Config,error)`; приватные wire-типы с json.RawMessage, строгие объекты через DisallowUnknownFields.
- Файл содержит только max_window_seconds и subsystems: load_average/cpu/disk_io/filesystems/traffic/connections.
- Port только CLI, не JSON. Пропущенные поля сохраняют defaults, явное false выключает. Все false допустимы.
- Пустой файл, null, неизвестные поля, неверные типы/диапазоны, второй JSON-документ/мусор — ошибка с нулевым Config. Ошибки reader оборачиваются через %w.
- Повторные JSON-ключи: последнее значение; повторные CLI-флаги также.
- CLI: локальный FlagSet; `parseArgs(args []string, output io.Writer) (config.Config,error)`, `run(args []string, stdout,stderr io.Writer) int`.
- `-port` 1..65535; `-config` явно задаёт путь; без него файл не ищется. `-config=` — ошибка.
- `-h`/`-help`: stdout и exit0, файл не читается. Неизвестные флаги/позиционные аргументы/ошибки конфигурации: stderr и exit2.

- `configs/stats-daemon.json` — полный рабочий пример, проверяется тестом.
