# Stats API v1

`stats.v1.StatsService.Subscribe` принимает `SubscribeRequest` и возвращает
server-side stream составных `Snapshot`. Схема — [stats.proto](stats.proto).
Сервер пока не реализован; этот этап определяет транспортный контракт.

## Семантика

1. N/M — целые секунды от 1 до 3600 (сервер может задавать предел M); N > M допустимо. Первый ответ через M секунд после принятия запроса, далее каждые N секунд. Клиентские значения по умолчанию N=5, M=15. Запрос содержит явно заданные N/M. Ноль не означает default. Нарушения диапазона впоследствии отклоняет сервер кодом `InvalidArgument`; proto3 сам их не валидирует.
2. Окно `[window_start, window_end)`, `generated_at` — время формирования сообщения. Временные метки UTC; все подсистемы одного снапшота относятся к одному окну.
3. `coverage_ratio` от 0 до 1 — доля окна, для которой есть пригодные данные. Средние рассчитываются по доступному времени, без подстановки нулей в пропуски. `last_sample_at` отсутствует при отсутствии измерений.
4. `UNSPECIFIED` — незаполненный статус, не успешный результат. `OK` — полный результат; `DISABLED` — сбор отключён; `UNAVAILABLE` — пригодных данных нет; `PARTIAL` — данные есть, но неполны. При DISABLED/UNAVAILABLE данные отсутствуют; при OK/PARTIAL сообщение данных присутствует, даже если списки пусты. Это договорённость API, не автоматическая проверка protobuf.
5. Для momentary-метрик соединений покрытие относится к доступности периодического сбора, а сами данные — к `last_sample_at`. Для них усреднение не выполняется.
6. CPU — проценты 0–100: user включает nice; system включает irq/softirq; idle не включает iowait; iowait и steal отдельные. Load1/5/15 — средние соответствующих системных показателей за M, без деления на число CPU.
7. Disk I/O — завершённые read+write операции/с и KiB/с по целым устройствам. Filesystems — средние использованные MiB, inode и проценты; inode как среднее имеет дробную часть. Неопределённый процент при нулевой ёмкости отсутствует. Идентификатор — mount point.
8. Трафик — IP-байты с IP-заголовком, IPv4/IPv6, направленные потоки, loopback по умолчанию исключён. Protocol percentages — относительно всего учтённого IP-трафика. Потоки отсортированы по bytes_per_second; top-K по умолчанию 20. Превышение лимита учёта потоков даёт PARTIAL. Ограничение выдачи top-K само по себе не означает потерю учёта.
9. Protocol задаётся числовым IP protocol number: 6 TCP, 17 UDP, 1 ICMP, 58 ICMPv6. Неизвестные номера сохраняются; закрытый enum протоколов не нужен. Порты 0–65535, отсутствие отличается от нуля. IP хранится строкой без порта и скобок, IPv6 также.
10. TCP-состояния передаются каноническими строками (`ESTABLISHED`, `SYN_RECV`, `FIN_WAIT1` и т.д.); будущие неизвестные состояния сохраняются. UDP в списке слушающих сокетов означает локально привязанные сокеты. Один сокет может иметь несколько владельцев — передаётся список, пустой при отсутствии доступа.
11. Не удалять и не переиспользовать номера полей; при удалении резервировать номер и имя. Изменения несовместимой семантики требуют новой версии API.
12. Ошибки сборщиков отражаются статусами, не завершают RPC. Отмена клиентом завершает подписку; таймауты, backpressure и реализация gRPC-кодов относятся к задаче 13.


Для DISABLED/UNAVAILABLE coverage_ratio=0, last_sample_at отсутствует.
При OK coverage_ratio=1; PARTIAL допускает coverage_ratio=1 при потерях,
не связанных с длительностью покрытия (например, превышении лимита потоков).
При нулевом суммарном трафике protocols пуст. Проценты заполненности:
used = total - free, percent = used / total * 100; inode — аналогично.
Средние и скорости при пропусках относятся к пригодной части окна,
а не ко времени без измерений; PARTIAL и coverage_ratio показывают это клиенту.
Все шесть секций и их статусы присутствуют в каждом снапшоте.
При равной сортировочной величине протоколы упорядочены по номеру;
потоки — по source IP/port, destination IP/port, protocol number;
адреса сравниваются как строки, отсутствующий порт предшествует присутствующему.

## Примеры (ProtoJSON-фрагменты)

Запрос: `{"intervalSeconds":5,"windowSeconds":15}`.

CPU с измеренным нулём: `{"cpu":{"status":{"state":"COLLECTION_STATE_OK","coverageRatio":1},"data":{"idlePercent":0}}}`.
Примеры ниже опускают временные метки и остальные секции для краткости.

Отключённая сеть: `{"traffic":{"status":{"state":"COLLECTION_STATE_DISABLED"}}}`.

Успешная пустая сеть: `{"traffic":{"status":{"state":"COLLECTION_STATE_OK","coverageRatio":1},"data":{}}}`.

ICMP без портов: `{"source":{"ip":"192.0.2.1"},"destination":{"ip":"192.0.2.2"},"protocolNumber":1,"bytesPerSecond":64}`.

Сокет без владельца: `{"local":{"ip":"::","port":8080},"protocolNumber":6,"owners":[]}`.

## Генерация

Go 1.27.3. Точные версии закреплены в [tools.env](tools.env):
protoc 36.2, protoc-gen-go v1.36.12, protoc-gen-go-grpc v1.6.2,
grpc-go v1.85.0, protobuf-go v1.36.12.

Скачайте архив protoc для своей ОС из официального релиза:
[Protobuf v36.2](https://github.com/protocolbuffers/protobuf/releases/tag/v36.2).
Распакуйте архив целиком, сохранив соседство `bin/` и `include/`,
и добавьте `bin/` в PATH. Проверьте `protoc --version`: `libprotoc 36.2`.
Нужны доступ к Go module proxy и доступный для записи Go cache.

Из корня репозитория выполните:

```sh
./scripts/generate-proto.sh
go mod tidy
go test ./pkg/api/stats/v1
```

Скрипт также работает из другого рабочего каталога через абсолютный путь.
Плагины устанавливаются в временный каталог, удаляемый при завершении.
Результаты: `pkg/api/stats/v1/stats.pb.go` и `stats_grpc.pb.go`.
Оба файла хранятся в Git; вручную их не редактировать.
Повторная генерация теми же версиями должна давать идентичные файлы.
